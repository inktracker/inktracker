### Theoretical issues agents flagged that I verified are NOT real

- **`messages_access` RLS doesn't include `shop_owner`** — agent claimed cross-shop leak. False: emails are unique per user, the policy correctly restricts to messages where the authenticated user is the sender OR recipient. Adding `shop_owner` would be redundant.
- **`createCheckoutSession` `.select("*")` leaks customer data** — verified: the customer object loaded internally is used for Stripe email lookup, not returned to the unauthenticated caller. The quote object IS returned, and the existing code annotates it as "public-safe" (lines around L94). Worth a future audit pass to narrow specific columns, but no current leak.
- **PR #243 broke production task auto-derive** — true in theory; fixed in #251 with the warning banner so shops can't trip it silently.

## Recent session pattern observations (for future-me)

This session shipped ~37 PRs (#168 through #251). Patterns to keep:

- **Auto-merge after CI green** is fast and safe. The two failures we hit (#218 orphan import, #237 CI env) were both caught by the new vite build CI step within 1 PR.
- **Migrations applied via `npx supabase db push`** worked without Docker (turns out `db push` runs against the remote directly; only `db diff` needs Docker).
- **The user's "Execute, don't ask" preference** is real and consistent — within an assigned task, make the call. They corrected me when I shipped UI hygiene without warrant (the auto-complete tightening on Account fields). When in doubt, fix and explain in the commit body.
